## Codeg UI Bridge 替换方案（Pi → Codeg 直连 + WebSocket 实时回传）

### 一、目标架构

```
浏览器扩展（content overlay + MV3 background）
   │  HTTP:  POST http://{ip}:{port}/api/<command>   (Authorization: Bearer <token>)
   │  WS:    ws://{ip}:{port}/ws/events              (子协议: codeg-events, codeg-token.<base64url(token)>)
   ▼
Codeg Web 服务
   │  ACP 子进程（acp_connect 拉起）
   ▼
pi / claude_code / codex / ... 任意 Agent CLI
```

- 删除整个 Pi 扩展宿主（本地 bridge-server 不再存在），扩展后台直接调 Codeg API。
- 已核实（codeg 源码）：CORS 全开（`src-tauri/src/web/router.rs:27-30`），manifest 已有 `<all_urls>` host_permissions，扩展可直接访问；全部命令为 `POST /api/<command>` + JSON body；WS 事件用 attach 协议（`ws_attach.rs`）。
- 关键接口：`/api/health`、`/api/acp_list_agents`、`/api/list_folders`、`/api/acp_connect {agentType, workingDir, sessionId?}`、`/api/acp_prompt {connectionId, blocks:[{type:"text",text}]}`、`/api/acp_cancel`、`/api/acp_touch_connection`、`/api/acp_respond_permission`、`/api/acp_answer_question`、`/api/acp_answer_plan_approval`、`/api/acp_get_session_snapshot`、`/api/acp_disconnect`、`/api/acp_list_connections`。

### 二、使用流程设计（对应你的两条要求）

**1. 连接配置**：popup 填三个字段 —— IP（默认 127.0.0.1）、端口（默认 23080）、Token，保存到 `chrome.storage.local`（不硬编码进代码）。「测试连接」按钮调 `/api/health` 校验并显示 Codeg 版本。

**2. 使用前准备（读取 Codeg 信息 + 选项目 + 选智能体）**：连接成功后 popup 自动拉取：
- 智能体下拉：`acp_list_agents`（默认 `pi`，可切 claude_code/codex 等）
- 项目下拉：`list_folders`（Codeg 中已登记的项目文件夹，显示 name + path）
- 选择后点「连接页面」：绑定当前 tab，`acp_connect {agentType, workingDir: 项目path}`，记录 connectionId
- 记忆映射：按页面 origin 记住「项目 + 智能体」组合，下次同站点自动预填
- 支持手动输入项目路径（调 `open_folder {path}` 登记后选用）

**3. 日常使用**：页面选元素 → 内联输入需求 → 发送 → 扩展 WS attach 后实时流式显示执行过程与结果，可随时「停止」（`acp_cancel`）。

### 三、WebSocket 实时回传设计（background 内单例 WS 管理器）

- 建连：`new WebSocket(url, ["codeg-events", "codeg-token." + base64url(token)])`，等 `__ready__` 帧后 `{"action":"attach","subscription_id":uuid,"connection_id":id,"since_seq":null}`。
- 事件消费：`snapshot` → 全量；`event` → 按 `envelope.type` 分发：`content_delta`（流式正文）、`thinking`（折叠展示）、`tool_call/tool_call_update`（工具执行卡片）、`turn_complete`（完成态）、`permission_request / question_request / plan_approval_request`（面板内展示选项，点击直接回 `acp_respond_permission / acp_answer_question / acp_answer_plan_approval`，避免回合卡死）、`error`。
- 断线恢复：按 `envelope.seq` 记录 lastSeq，重连后 `attach {since_seq: lastSeq}` → `replay` 补帧或 `snapshot` 兜底；`detached(connection_gone)` 时自动 `acp_connect` 重建（携带已存 `external_id` 作为 `sessionId` 恢复会话历史）。
- MV3 保活：Chrome ≥116 WS 活动可续命 SW；另加 20s 应用层 `{"action":"ping"}`；面板打开期间 content script 也会驱动后台保活，SW 重启后自愈重连。

### 五、关键风险与对策

- Codeg API 无公开文档承诺，但官方 iOS/Android 客户端使用同一协议，事实稳定；客户端封装集中在 `codeg-api.ts` 一个文件，便于跟随演进
- Codeg 默认 60s 空闲回收连接：面板打开期间 touch 保活；回收后经 sessionId 重连恢复上下文
- 请求体上限 2MiB：纯文本 prompt 远小于限制
- Token 只存 `chrome.storage.local`，不进代码仓库

### 六、验证方式

`pnpm typecheck` + `pnpm build:browser-extension`；`pnpm dev:react-demo` 起演示页 → popup 填 127.0.0.1:23080 + Token → 测试连接 → 选项目/智能体 → 连接页面 → 选元素发送 → 在面板中确认流式回复与 tool_call 展示、完成后状态正确；验证停止按钮、断开 Codeg 后的错误提示、空闲超时后重连恢复会话。
