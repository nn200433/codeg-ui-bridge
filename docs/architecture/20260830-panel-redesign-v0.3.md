# Codeg UI Bridge 面板重设计方案（v0.3 提案）

> 日期：2026-08-30
> 状态：提案（待评审，未实施）
> 范围：页面侧悬浮面板（content.ts）信息架构重排、popup 加宽；不改 bridge 协议与 prompt 数据结构。

## 1. 背景与目标

插件定位：**让 AI 帮用户定位页面问题，并辅助调整页面。**

用户的主循环只有三步：

1. 选中页面元素（告诉 AI"改哪里"）
2. 用一句话描述需求/问题（告诉 AI"改什么"）
3. 看 AI 执行结果（流式回复、确认卡片）

当前面板把主循环和一堆开发者调试工具混在一层，导致"功能很迷"。

## 2. 现状诊断

当前展开态自上而下（content.ts `renderPanel`）：

| 区块 | 内容 | 问题 |
|------|------|------|
| 顶栏 | 断开 / 中EN / 收起 / × | 尚可，但按钮偏多 |
| 工具条 | 选择:开/关、刷新 | 刷新已被自动化取代，价值低 |
| 选中元素卡 | 元素标签 + domPath + semanticPath + rect | 3 行技术数据无人阅读 |
| 源码卡 | 源码 chip + component + sourceId | 同上，且多为空（依赖 source-binder 注入） |
| 按钮排 | DOM / 定位 / 复制源码 | **定位=复制 file:line，复制源码=复制 sourceId/file——本质是两个重复的"复制"按钮** |
| 次按钮排 | 复制 JSON | 纯调试用途，常驻喧宾夺主 |
| 需求区 | textarea + 发送 | **无论是否选中元素常驻可用**，用户不知道 AI 能否知道"改哪里" |
| 流式区 | 回复/工具/审批卡片 | 核心价值，但被上面的噪音淹没 |
| 底部 status | 一行文本 | 与副标题状态重复 |

另一个事实：**选中元素时元素旁已会出现悬浮快捷输入框（inline composer，含需求+发送）**，这正是用户期望的交互，但它视觉存在感弱，且面板内又有一套常驻需求框，两条路径并存、分工不明。

## 3. 重设计原则

1. **面板 = "选中什么 + 跟 AI 说什么 + AI 干了什么"**，其余一律收进折叠区。
2. **主路径上下文驱动**：未选中元素 → 输入置灰并引导；选中 → 输入激活；发送后 → 会话流自动展开。
3. **调试能力降级不删除**：复制定位、复制 JSON、DOM 浏览器收进"详情"折叠区。
4. **数据协议不动**：`buildBridgePrompt` 依旧携带完整结构化数据与源码绑定，UI 收起不代表 AI 拿到的信息变少。

## 4. 信息架构：L1 / L2 / L3

- **L1 主路径（常驻）**：选择开关 → 选中元素卡（1 行人话 + 1 行源码定位）→ 需求输入 + 发送。
- **L2 会话流（发送后展开）**：AI 回复、工具调用、权限/提问/计划审批卡片。
- **L3 详情（默认折叠）**：DOM/语义路径、rect、源码绑定细节、DOM 结构浏览器、复制定位信息、复制 JSON、语言切换、刷新连接。

## 5. 界面线框

### 5.1 面板展开态

```
┌────────────────────────────────────┐
│ ● Codeg Bridge              ⏻  ▴  ×│   顶栏：状态点 + 断开 + 收起 + 关闭（拖拽区）
├────────────────────────────────────┤
│ [⬚ 选择元素]  ● 选择中              │   选择开关（主 chip，显眼）
│                                    │
│ ┌────────────────────────────────┐ │
│ │ 🎯 button · "提交订单"          │ │   选中元素：1 行人话
│ │ 📄 src/pages/Order.tsx:42  ⧉   │ │   1 行源码定位（点 ⧉ 复制定位信息）
│ └────────────────────────────────┘ │
│ ┌────────────────────────────────┐ │
│ │ 描述你要的改动，或这里的问题…    │ │   需求输入（未选中置灰，引导文案）
│ │                                │ │
│ │                      [发送 ▶]  │ │
│ └────────────────────────────────┘ │
├────────────────────────────────────┤
│ ▾ AI 执行中…                       │   L2 会话流（发送后自动展开）
│   ▸ 读取 Order.tsx                 │
│   ▸ 编辑样式                       │
│   ✓ 完成：变更 1 个文件              │
├────────────────────────────────────┤
│ ▸ 详情                             │   L3 折叠区
└────────────────────────────────────┘
```

未选中元素时，选中卡显示为引导位："点击页面任意元素，AI 将以它为上下文"。

### 5.2 悬浮快捷输入（保留并强化为主路径）

选中元素即出现在元素旁（现 inline composer 增强）：

```
      ┌────────────────────────────┐
      │ 🎯 button · "提交订单"  [×] │
      │ ┌────────────────────────┐ │
      │ │ 要改什么？              │ │
      │ └────────────────────────┘ │
      │        [面板中展开] [发送▶] │
      └────────────────────────────┘
```

- 就近发送：输入完直接回车/点发送，不必去面板。
- `面板中展开`：跳转面板继续（会话流在面板）。
- 发送后悬浮框收起，状态流转到面板会话流。

### 5.3 面板收起态

```
┌──────────────────────────────┐
│ ●  [⬚ 选择]  ▾ 展开           │
└──────────────────────────────┘
```

### 5.4 Popup

宽度 400 → **480px**（Chrome 上限 800，480 为舒适值），布局沿用现有版本不变。

## 6. 关键交互决策（附推荐）

| 决策点 | 推荐 | 理由 |
|--------|------|------|
| 选中元素后选择模式是否自动关闭 | **是**，点击元素即锁定；重选需再点"选择元素"或 Esc | 防止后续点击误改选中对象；现状态选中后仍处于选择模式，极易误选 |
| 悬浮输入与面板需求框是否并存 | **并存，分工明确**：悬浮=就近快发；面板=会话中心 | 悬浮已是用户期望的交互，砍掉可惜；混乱源于面板，而非悬浮 |
| 定位 / 复制源码 / 复制 JSON 三个按钮 | **合并为 1 个"复制定位信息"**（选中卡右侧 ⧉，复制 file:line + selector）；复制 JSON 移入详情 | 前两者功能重复；JSON 仅调试时用 |
| 刷新按钮 | 移除（连接已自动化刷新），详情区保留一个文本入口 | attach 时已发 refresh-runtime |
| 中/EN 切换 | 移入详情折叠区 | 低频功能不占顶栏 |
| 底部 status 行 | 删除，状态只在顶栏状态点+文字 | 消除重复 |
| 快捷预设 chips（"改样式/对齐间距/排查此元素问题"一键填模板） | **P1 做** | 直接服务"辅助调页面"目标，但不阻塞重排 |

## 7. 功能去留清单

| 现有功能 | 去留 | 去处 |
|----------|------|------|
| 选择开关 | 保留强化 | L1 主 chip |
| 选中元素信息 | 精简为 2 行 | L1 选中卡 |
| 源码绑定信息 | 保留展示 1 行 + 完整进详情 | L1 / L3 |
| DOM 浏览器 | 保留 | L3 详情入口 |
| 定位、复制源码 | 合并 | L1 ⧉ 一键复制定位 |
| 复制 JSON | 保留 | L3 |
| 需求输入+发送 | 保留，随选中启用 | L1 核心 |
| 流式区+审批卡片 | 保留 | L2 |
| 断开/收起/关闭 | 保留 | 顶栏 |
| 语言切换 | 降级 | L3 |
| 刷新 | 降级 | L3 |

## 8. 实施分期

- **P0（本次重排）**：面板 L1/L2/L3 信息架构、顶栏精简、需求区随选中启用、复制按钮合并、删除重复状态行、popup 加宽至 480、悬浮输入框视觉强化 + "面板中展开"入口。
- **P1**：快捷预设 chips；选中后自动退出选择模式；会话流视觉优化（工具调用折叠、成功/失败态着色）。
- **P2（增强，另行评审）**：页面问题诊断增强——发送时可选附带该元素的 computed style、控制台报错；截图标注需求。

## 9. 明确不改的部分

- `buildBridgePrompt` 与 ApplyRequest 数据结构（AI 定位能力之源）。
- bridge-core 协议、popup 连接逻辑（上轮刚验收）。
- 权限/提问/计划审批的应答链路。
